# Katchimera Mascot Creation Process

This document defines how to create flagship Katchimeras from first principles when the goal is:

- stronger brand characters
- stronger social shareability
- better short-form video performance
- better memorability than the current catalog-first process

This process is specifically for:

- flagship mascots
- recurring marketing characters
- onboarding leads
- TikTok / Reels / Shorts character development

It is not meant to replace the full encounter catalog process.
It is meant to sit above it.

## 1. Why The Current Process Is Not Enough

The current encounter pipeline is:

- encounter seed
- 4 variants per seed
- prompt generation
- catalog output

That is good for:

- breadth
- coverage
- understandable unlock logic
- a large collectible catalog

It is not ideal for flagship mascot creation because it optimizes for:

- taxonomy coverage
- trigger variety
- systematic catalog generation

It does not optimize first for:

- viral personality
- repeatable comedy
- animation friendliness
- cast dynamics
- iconicness

So for the flagship tier, the process should be reversed.

## 2. New Rule

For flagship mascots:

- do not start with `what encounter needs a variant`

Start with:

- `what character would people instantly love, understand, and share`

Then map that character back into:

- encounter logic
- life reflection logic
- collectible logic

## 3. Mascot-First Pipeline

Use this order:

1. `content archetype`
2. `lifestyle niche`
3. `comedy engine`
4. `visual gimmick`
5. `motion language`
6. `reflection meaning`
7. `encounter mapping`
8. `catalog family fit`

### 3.1 Content archetype

Define the internet-readable archetype first.

Examples:

- over-serious coffee gremlin
- tiny bakery diva
- chaotic city goblin
- sleepy anti-chaos blanket spirit
- over-motivated workout friend

This is the part that determines whether the mascot can carry content.

### 3.2 Lifestyle niche

Attach the archetype to a recognizable life pattern.

Examples:

- cafe regular
- bakery person
- park walker
- night owl
- homebody
- runner

This keeps the character anchored in the product.

### 3.3 Comedy engine

Define the repeatable bit.

Examples:

- treats coffee like religion
- hoards pastries like treasure
- gets overstimulated by city signs
- wants everyone to go to bed immediately

If the mascot does not have a repeatable bit, it is not ready.

### 3.4 Visual gimmick

Pick one instantly readable feature.

Examples:

- ceramic cup hood
- brioche ears
- moss hood
- signal-light ears
- blanket tail

This should make the creature recognizable even in silhouette or sticker form.

### 3.5 Motion language

Define how it moves.

Examples:

- careful tiny steps
- soft bounce hops
- jittery freeze-turns
- droopy wrap-and-settle drift

This makes the character usable in video.

### 3.6 Reflection meaning

Only after the character is strong should the life meaning be attached.

Examples:

- ritual
- comfort
- return
- recovery
- momentum
- wonder

This keeps the app truthful without weakening the character.

### 3.7 Encounter mapping

Now map the character to one or two strong encounter sources.

Examples:

- Lattelet -> cafe / home coffee
- Mossprout -> park / green routine
- Hushling -> home / calm evenings
- Neonpoko -> night-city / landmark urban crossing

### 3.8 Catalog family fit

Finally decide:

- does this become a new family
- a premium flagship variant
- a replacement for a weaker existing mascot

## 4. Flagship Creation Gates

Before approving a new flagship mascot, it must pass all of these:

### Gate 1: One-line description test

Can the mascot be described in one line?

Examples:

- `tiny barista gremlin`
- `sleepy blanket ghost who hates plans`
- `night-city chaos bunny`

If not, it is too vague.

### Gate 2: Silent reaction test

Would the character still be funny with no dialogue?

If not, the visual acting is too weak.

### Gate 3: Thumbnail test

Would the character still read in a small feed preview?

If not, the silhouette is too weak.

### Gate 4: Lifestyle recognition test

Would a user say:

- `that is so me`

If not, the niche is too abstract.

### Gate 5: Repeatability test

Could this mascot appear in 20 different short-form clips without becoming unclear?

If not, it is not strong enough.

## 5. Replace vs Keep Strategy

The right question is not:

- `which of the current ones should be our mascots`

The right question is:

- `which current ones are strong enough to survive mascot-first selection`

Use this framework:

### Keep

Keep a current mascot if it already has:

- instant read
- memorable visual gimmick
- obvious personality bit
- good motion potential

### Rebuild

Rebuild a current mascot if:

- the core niche is good
- but the current design is too generic or weak

### Replace

Replace a mascot entirely if:

- the encounter category matters
- but the current concept does not have flagship potential

## 6. Greenfield Creation Track

Create new mascots from scratch when:

- the content opportunity is stronger than the current catalog option
- the current lineup lacks a specific archetype
- a stronger personality can still map cleanly to real-life reflection

Recommended greenfield archetypes to explore:

- `bedrot royalty`
  home / recovery / anti-plan humor

- `errand gremlin`
  grocery / mall / practical-day humor

- `bookstore overthinker`
  quiet culture / introvert identity

- `bubble tea flirt`
  bright treat-stop / playful social content

- `dog-park goblin`
  social outdoor chaos

- `museum snob but cute`
  cultured curiosity with attitude

## 7. Stronger Creation Template

Use this template for each new mascot concept:

### Mascot concept sheet

- `Working name`
- `Content archetype`
- `Lifestyle niche`
- `Main encounter source`
- `Secondary encounter source`
- `Reflection meaning`
- `Visual gimmick`
- `Core silhouette`
- `Motion language`
- `Comedy engine`
- `Reaction range`
- `Shareability rating`
- `Video potential rating`
- `Catalog fit`
- `Keep / rebuild / replace`

## 8. Recommended Workflow

### Step 1

Write 20 possible mascot archetypes with no concern for current catalog constraints.

### Step 2

Cut that list to the 8 with the strongest:

- one-line premise
- lifestyle recognition
- comedy engine
- visual gimmick

### Step 3

Map the winners back to:

- encounters
- emotions
- reflection meaning

### Step 4

Check whether each winner:

- fits an existing Katchimera
- should replace one
- should be invented fresh

### Step 5

Only then produce:

- names
- motifs
- prompts
- reveal copy

## 9. Practical Conclusion

For the flagship tier:

- the catalog should not be the starting point

The starting point should be:

- `character potential`

Then:

- connect the character back to life reflection

This preserves the app’s concept while making the mascots much stronger.

## 10. Final Direction

The best flagship Katchimeras should be:

- character-first
- reflection-backed
- encounter-grounded

Not:

- encounter-first variants that happen to be decent characters

That is the difference between:

- a collectible system

and:

- a real mascot universe
